# Architecture

Browser (Vite React SPA :5180) -> FastAPI (:8100) -> MongoDB 7 (compose network only, auth on). External: TCGdex (catalog + Cardmarket prices; pokemontcg.io selectable until its keys end 2027-03-01), frankfurter.dev (FX). Scraped price sites are reached only through the host-Mac **fetcher** (below).

## Backend layering

`api/` (thin routers) -> `services/` (logic) -> `providers/` (only place that does HTTP) + `db/`.

| `services/alerts.py` | price alert rules + state machine (`alerts`, `alert_events`), system inbox items, unread count |
| `services/refresh.py` | price refresh job (`tracked` = collection + wishlist, `collection`, `wishlist`; `sets` narrows) then snapshot; `refresh_card_price` = one-card fetch (user action); `price_new_tracked` = background fetch when a card joins collection / wishlist. `pricing.tracked_card_ids` is the price-scope rule |

| `providers/fetcher.py`, `providers/price/{pricecharting,cardmarket,altxyz,match,resolve}.py` | fetcher HTTP client; scraped-site adapters + matcher (see pricing.md) |
| `services/price_fetch.py` | on-demand scraped fetch job `price_fetch` (cards / sets / owned x sources): adapters -> `prices` + `latest_price`, records matches, `fetch_log` (`{card_id}\|{source}`: status, detail, url, fetched_at), snapshot at end. Bulk (`mode` all/never/stale/valuable/stack via `resolve_bulk(..., scope=collection|wishlist|both)`; both = owned first then wishlist-only, deduped; stats carry `scope`, `alerts_fired`): stats carry `eta_s` (remaining x observed pace of real fetches, pause time excluded), `paused`, `ok_cards`; `failures` / `needs_match_list` entries have `{card_id, name, source, reason}` (reason = no match / blocked / layout changed / failed). Pause / resume / cancel = `control` field on the running `jobs` doc (`jobs.set_control`), polled between pairs by `_checkpoint`; a paused job stays `running` (keeps the one-at-a-time index), cancel ends as status `cancelled`. Bulk runs raise one `notify_system` inbox item (`price_fetch_done:<job>`) that the fetcher notifier shows as a macOS notification. After a run with `ok` > 0, `_after_run` takes the snapshot only if an owned card updated (it evaluates alerts) else calls `alerts.evaluate`, failures only logged. `price_freshness` (owned + `wishlist` sub-dict) feeds `/collection/summary.prices`; `wishlist_freshness` feeds `GET /api/wishlist/prices`. Endpoints `POST /api/admin/prices/fetch`, `POST /api/cards/{id}/fetch-prices` (202; 422 bad target/source; 503 fetcher down; 409 running) |
| `providers/ocr/` | `get_ocr()` (`OCR_PROVIDER`, `tesseract`). `cardgeom.py`: `find_quad` (OpenCV contours -> 63:88 quad, None when cut off / not card-shaped) and `warp` (630x880, optional inset), `flats` (sleeve readings) with `locate_card` (card box inside a flat sleeve by border edge strength) and fixed-box `sleeve_crops` as fallback; `fields.py`: pure parsers for number / set code / HP; `TesseractOcr.read_fields` (voted digits-only reads of the number regions, set code, HP; `CardFields.votes` = agreeing reads, gates `exact` in `services/scan.py`) and `stages` (flat card first, brightness stages as fallback). Older reader: `TesseractOcr.read_lines(image)`: Pillow decode (JPEG/PNG/WebP only, 40 Mpx cap, EXIF turn, grayscale, autocontrast, 1000 px wide), top 20 % band read in sparse mode (`--psm 11`) and line mode (`--psm 7`), whole image as fallback; subprocess with 10 s timeout, max 2 at once. Errors: `ImageError` (400), `OcrUnavailable` (503) |
| `providers/ocr/imagematch.py`, `providers/catalog/images.py`, `services/artmatch.py` | Artwork fallback: `photo_arts` (art crops of the photo's flats), `inliers` (SIFT + RANSAC), `fetch_image` (only downloader of catalog images), `artmatch.matching` (caches art crops in `art_cache`, returns ids of prints whose art matches; failures return an empty set) |
| `services/scan.py` | `identify` (OCR lines -> word windows -> exact `name_norm` match, difflib fuzzy 0.75 only when nothing is exact -> every card of the best <= 3 names, scored by agreeing signals (name, number or the weaker partial number when OCR dropped the leading digit, printed total, set code from `read_fields`, artwork match when the number was not read twice; number + printed total alone also find prints when no name is read), then owned first / newest set, max 40, `signals` + `match_label` per card, `read` + `exact` per response, `confidence` high/medium/low/none, `edition_note` for sets with unmarked 1st Edition / Shadowless prints), `search` (typed name, same card shape), `add_scanned` (= `collection.add` stack merge + a `scan_events` row), `events_after` (cursor poll for the laptop, optional `session_id`), `lookup` (typed number/printed total + set code/id/name -> same shape as `identify`), `start_session` / `current_session` / `close_session` (laptop-opened session, 30 min idle expiry), `undo` (last add only, 10 min). Never adds on its own |
| `security.py` | phone-mode gate: a request with a valid `X-Moc-Gate` may only call `PHONE_ALLOWED` (below) from the tailnet host/origin; a wrong header is 403; no header = laptop, unchanged |
| `services/sales.py` | `store_sales` (scraped sold listings, dedupe on listing id), `store_chart_seed` (PriceCharting monthly history as `seed` observations) |
| `services/matching.py` | persisted card -> product URL per scraped source (`product_matches`), URL validation, user/auto precedence |
| `jobs/scheduler.py` | APScheduler, only if `SCHEDULER_ENABLED`: tasks `daily_refresh`, `daily_fetch` (scraped, unattended, capped), `daily_snapshot`, `weekly_catalog`, `daily_prune` (deletes read alert events older than `ALERT_EVENTS_KEEP_DAYS`, 90; 0 = keep; housekeeping, never caught up), each via `run_task` (failures and busy job types are logged, never propagate). Boot `catch_up` runs overdue tasks once, in the background. `jobs` rows carry `trigger` = `manual`\|`scheduler`\|`catchup`; a scheduled fetch with the fetcher down is a `skipped` row |

Long jobs run as asyncio tasks; state is persisted in the `jobs` collection (UI polls `/api/admin/jobs`). One `running` job per type: API returns 409, and a partial unique index on `jobs.type` (status=running) is the race-free backstop. Orphaned `running` jobs are marked `interrupted` on boot.

## Phone scanning (Tailscale, opt-in)

```
iPhone --https--> tailscale serve (host Mac) --http--> Caddy 127.0.0.1:5443 (compose profile `lan`, off by default) --> app:8000
```
Caddy (`lan/Caddyfile`): needs `Tailscale-User-Login == MOC_TS_LOGIN` (Tailscale sets it after authenticating the device), serves `web/dist` for `/scan`, `/assets`, manifest, proxies only the paths below with `X-Moc-Gate: <secret>`, caps bodies at 10 MB, answers 403 on any other `/api/*`, redirects everything else to `/scan`. The app re-checks the allowlist, the Host (must be the tailnet host, which `lan/lan.env` adds to `ALLOWED_HOSTS`) and the Origin (only `LAN_ORIGIN`; the laptop origin does not work from the phone). Secrets live in gitignored `lan/lan.env` written by `scripts/lan.sh`, which is an optional second `env_file` of `app` and `lan`; without it phone mode is off and any gate header is refused.

| Reachable from the phone | Laptop only (403 through the gate) |
|---|---|
| `GET /api/scan/me`, `POST /api/scan/identify` (raw image body, 8 MB cap), `GET /api/scan/search?q=`, `GET /api/scan/cert?grader=&cert=`, `GET /api/scan/ja/suggest`, `GET` + `POST /api/scan/ja/import?set=` (one validated ja set into the catalog, never the collection; see below), `POST /api/scan/photo` (a photo for a just-scanned stack), `POST /api/scan/add` (body = `CollectionIn`), `GET /health` | `/api/scan/status`, `/api/scan/events`, and all of `/api/collection/*` (list, export, import, patch), `/api/cards/*`, `/api/admin/*`, wishlist, alerts, dashboard, `/docs` |

`cert_cache` `{_id 'GRADER:cert', status, info (CertInfo doc), lookups, fetched_at, expires_at}`: TTL on `expires_at` (found 30 d, not_found 1 h, link_only 7 d; blocked / unavailable / invalid never stored); `lookups` counts scans so unsupported (link-only) graders are countable. `services/slab.py` matches a found cert to catalog prints set-first (page set string + year -> up to 3 catalog sets, then card name words inside them, global name fallback; rarity word = bonus signal, noise list instead of exact equality) by name + number + printed total (+ set / year / rarity bonus): ACE can be `exact`, PSA / BGS cap at `likely` and `needs_confirm` is true. the cert answer also has `warnings` (grade / tier vs label, non-Pokemon page, cert length) and `GET /api/scan/certs/recent` (laptop only) lists the last lookups with their match. Phone side: `components/scan/SlabResult.tsx` renders the cert answer in slab mode (page summary, `warnings`, grader / cert edit -> `api.scanCert(grader, cert, {grade, tier})` again), above `CandidatePicker` (`quiet`) and `AddSheet`. `identify?slab=1` no longer runs `identify_card`: it reads the label (`providers/ocr/slab.py`: `find_slab` -> `locate_label` -> read only the label crop, tile reader as fallback; per-grader cert rules in `slabfields.py`, see decisions.md "Slab label: locate, then read only it"), looks the cert up (only `cert_sure` reads, `slab_certs`, at most 2) and returns `cert` + `cards`. `collection_items.grading` gains server-derived `report_url` (fixed template) and `cert_info` (cached page), never taken from the request. `scan_sessions` `{status open|closed, mode raw|slab (missing = raw), created_at, last_activity}`; `POST /api/scan/sessions` takes an optional JSON body `{mode}` (default raw, 422 on anything else) and `GET /api/scan/session` returns `{id, created_at, mode}` (TTL 1 day; one open at a time). `collection_exits` `{card_id, stack snapshot (variant, language, condition, grading, acquired), quantity, reason sold|gifted|removed, price, currency, date, note, created_at}`: written by `services/collection.remove` for every sale / gift / removal, never deleted. `scan_events` `{at, kind add|undo, card_id, label, stack_id, quantity_added, quantity_after, type_conflict, condition, language, session_id, existed, prev_acquired, undone, undoes}`: TTL `SCAN_EVENT_KEEP_DAYS` (7). The laptop (`ScanToast`, mounted in `App`) polls `GET /api/scan/events?after=<id>` every 4 s only when `/api/scan/status` says phone mode is on; the first call returns just a cursor (no history), later calls return new events, which invalidate the `collection` / `cards` / `card` queries and show "Added: ...".
Import-a-Japanese-set prompt (2026-11-10): when a photo / typed number / cert finds no print, `Scan.tsx` shows `components/scan/JaImportPrompt.tsx`. `GET /api/scan/ja/suggest?code=&total=&set_name=&q=` (`services/ja_suggest.py`) ranks the live TCGdex ja list (cached 10 min): printed set code = set id (10), English set name via `app/data/ja_set_aliases.json` (6; ja names are kana), search (5), printed total only as a bonus (3); no signal = []. `POST /api/scan/ja/import?set=ID` accepts one id from that list, `ensure_idle('catalog_import')` (409), spawns `catalog_ja.import_ja_sets([id], trigger='scan')` (job `catalog_import`, `stats.language='ja'`); `GET /api/scan/ja/import` reports `{state idle|running|done|partial|error, set, done, expected, failed}` (cards held / set total). On done the page re-runs the match (raw: the kept photo; slab: the cached cert lookup). A phone can therefore start one bounded catalog import; nothing else under `/api/admin` opens. `lan/Caddyfile` and `PHONE_ALLOWED` list the same paths (test `test_caddy_gate_forwards_exactly_the_app_phone_allowlist`).
Config: `LAN_GATE_SECRET`, `LAN_ORIGIN`, `LAN_LOGIN` (display), `OCR_PROVIDER`, `TESSERACT_CMD`, `SCAN_MAX_IMAGE_MB` (8), `SCAN_EVENT_KEEP_DAYS` (7). The app image installs `tesseract-ocr` + English data; Pillow is a dependency. `api.ts` `BASE` is `VITE_API_URL ?? http://localhost:8100`; the phone build passes an empty value (same origin).
Frontend: `/scan` (`pages/Scan.tsx`) is its own shell in `App` (no laptop nav, no laptop polling). `components/scan/`: `CameraCapture` (rear camera + card-shaped guide, tap to capture, crop to the guide, <= 1000 px JPEG; without `getUserMedia` / secure context the native camera through `<input type=file capture>`), `CandidatePicker`, `AddSheet` (condition / print / language / copies / `AcquiredForm` via its new `onChange` + `hideSubmit`; last choice remembered in localStorage `scan.choice`), `PhoneLink` (QR via `qrcode`, in a Drawer on the Collection page), `ScanToast`.

## Fetcher (host Mac, `fetcher/`)

Separate small FastAPI service, not in docker-compose, bound to `127.0.0.1:8110`. The app reaches it at `FETCHER_URL` (default `http://host.docker.internal:8110`). The app never launches browsers; the fetcher never touches Mongo.

Alert notifications: `fetcher/notify.py` (asyncio task started in the fetcher lifespan, `FETCHER_NOTIFY_ENABLED`) polls the app's `GET /api/alerts/events?unread=true` every 60 s and shows a macOS notification via `osascript` for events newer than a high-water mark kept in `~/.moc-fetcher/notified.json`. It only reads from the app; no backend change.

Engine: real Google Chrome started by the fetcher with `--remote-debugging-port` and a dedicated profile (`~/.moc-fetcher/profile`, never the user's main profile), driven by Playwright `connect_over_cdp`. Browser starts on first request and closes after an idle timeout or `POST /close`.

- Sites: built-ins in `fetcher/sites.py` (pricecharting, cardmarket, altxyz, psa, beckett for slab cert pages) merged with `~/.moc-fetcher/sites.json` re-read per request (`{id, hosts, min_interval_s, cookie_button?}`), so adding a site needs no restart; `GET /health` lists the site ids. Done in 5f slice 2; `scripts/fetcher.sh restart`; unattended fetches wait the challenge grace; see decisions.md "Slab identity from the cert".
- `POST /fetch/{site}` `{url, wait_selector?, click_text?, click_labels?, pages?, next_label?, wait_ms?, timeout_s?}` -> `{status: ok|login_timeout|blocked|error, final_url, title, html, htmls, detail}` (`pages` > 1 + `next_label`: one load, one snapshot per list page in `htmls`, `html` = first). Sites: `pricecharting`, `cardmarket`, `altxyz`; URL host must belong to the site (no open proxy).
- `click_text` (optional): clicked after load / `wait_selector` (alt.xyz "Sold listings" toggle), after a short hydrate delay.
- `click_labels` (optional, max 10): elements clicked in order by exact `aria-label` after `click_text` and `wait_ms`, each followed by `wait_ms` (alt.xyz "Go to next page"). A DOM click event, because Playwright's scroll-into-view hangs on alt.xyz's inner scroller. Missing label = `error`.
- `GET /status` -> browser up/down, per-site `idle|fetching|waiting_login`. `POST /close`, `GET /health`.
- Per-site limiter: concurrency 1, min interval 3-5 s (+jitter).
- Flow: always try anonymous first. On a login wall or Cloudflare challenge the tab is brought to front on the site's page, state `waiting_login`, polled until cleared or `LOGIN_TIMEOUT_S`; credentials are never read. Screenshot saved on failure.

## Data model (collections)

- `cards`: `_id "pokemon:base1-4"`, tcg, name, `name_norm`, `search_text`, set{}, images, variants[], `latest_price{source{variant{market,low,avg,high,currency,as_of}}}`, `price_base` (cents, base currency). Indexes: text, name_norm, (tcg,set,number), rarity, types.
- `sets`: one per set.
- `collection_items`: one doc per stack, unique `stack_key` = card|variant|language|condition|grader|grade|cert. Add = `$inc quantity`; remove to 0 deletes.
- `collection_items.acquired`: `{type purchased|pulled|traded|gift|other|null, price (cents PER COPY, 0 = free, null = unknown), currency, date, source (where bought)}`; stack cost = price x quantity. No migration: stacks created before types have `type` null ("Not set", counted as non-pulled). Notes stay in the item-level `notes`.
- `collection_items.sale`: `{status ready|listed|reserved|withdrawn, listings[{platform vinted|cardmarket|ebay|marktplaats|other, asking_price (cents per copy), currency, listed_at, url, notes, shipping, asking_base (base-currency cents, frozen when saved)}], updated_at}`; absent = not for sale (no migration). Whole stack, not per copy. `services/sale.py`. A sale is a `collection_exits` row (`platform`, `fees`, `shipping_paid`, `realised`, `listed_days`, `delist`), written by `collection.remove`.
- `publish_queue` (roadmap 6e): `{item_id, card_id, state confirmed|publishing|published|failed|cancelled, mode create|update, url, payload {title, description, price, currency, condition, parcel, category, brand}, photos, error, created_at, updated_at}`; index `(state, created_at)`. One active entry per stack. `services/publish_queue.py`; claiming writes the stack's photos (cover first, max 20) to `publish_tmp/<id>/NN.jpg` (host-visible bind mount `./publish_tmp`, gitignored, removed on result / release / cancel).
- `photos`: `{stack_id (str), kind front|back|corner|surface|slab_front|slab_back|other, cover, order, data (JPEG, long side <= 1600), thumb (320), w, h, bytes, created_at}`; index `(stack_id, order)`. Belongs to the stack (copies are only a counter); deleted with the stack (`collection.remove`, scan undo). `services/photos.py` compresses with Pillow (EXIF applied then dropped), limits `PHOTO_MAX_PER_STACK` (12), `PHOTO_MAX_SIDE`, `PHOTO_QUALITY`, `PHOTO_THUMB_SIDE`; included in `scripts/backup.sh` (`--no-photos` skips).
- `collection_edits`: log of `acquired` changes `{item_id, stack_key, card_id, at, action edit|bulk|merge|import|restore, before, after}` (full subdocs, never pruned, survives stack deletion). Index `(item_id, at desc)`.
- `prices`: unique (card, variant, source, kind, grade_key, as_of); `kind` market | sold | listing_low. Re-refresh same day = same doc.
- `sales`: sold records, manual (`POST /cards/{id}/sales`) and scraped (unique `(card_id, source, listing_id)` when `listing_id` is set); stats: last 10 within 90 days per source+grade.
- `collection_snapshots`: unique per date (+ `valuation_version`, `needs_price_count`, `ref_raw_value` from Phase 9.2); `totals_by_source`, `total_value`, `value_kind_breakdown`, `estimated_count`, cost, counts, unpriced counts, breakdowns (pre-Phase-4 docs lack the first three). Step 3 adds `total_cost_ex_pulled`, `cost_basis_value`, `pulled_value`, `cost_missing_count` (older docs lack them; `total_cost` unchanged).
- `product_matches`: `_id "{card_id}|{source}"`, `url`, `confirmed_by` auto|user|null, pending `candidates`; only `pricecharting`, `cardmarket_web`.
- `list_presets`: saved filter sets `{scope collection|wishlist, name, query{param: string}, created_at}`, unique `(scope, name)` (saving the same name overwrites). Stored in Mongo, not localStorage, so they follow the user across devices (the phone in Step 5).
- `wishlist`: one doc per wanted version, unique `wish_key` = card|variant|grader|grade: `{card_id, variant, grading{company,grade}|null, target_price (cents), note, alert, created_at}`. Valued as a virtual one-copy item (`collection.valuate_wishlist`); never part of collection valuation, totals or snapshots.
- `alerts`: rule `{scope stack|card|total|wish, wish_id, item_id|card_id, op above|below|up_pct|down_pct, threshold (cents or %), days, kind, include_estimated, enabled, triggered, last_value, last_pct, last_eval, label}`.
- `alert_events`: `type alert|system|reprice|sold_comp` (reprice / sold_comp carry a unique `key`: `reprice:<item>:<platform>:<day>`, `sold:<item>:<sales id>`), rule text, card, `value/prev/pct`, kind/match/thin/estimated, `fired_at`, `read`; system items carry a unique `key` (one per day per reason). Index `(read, fired_at)`. Read events older than `ALERT_EVENTS_KEEP_DAYS` (90) are pruned by `daily_prune` (`alerts.prune_events`); unread ones never.
- `fx_rates`, `jobs`.

Money: integer cents + currency everywhere. Missing price = `null`, never 0.

## API (prefix `/api`; Swagger at `/docs`)

`GET /cards` (incl. `has_price`), `/cards/{id}`, `/cards/{id}/prices`, `POST /cards/{id}/sales`, `GET /cards/{id}/price-matrix` (grades/graders derived from stored rows), `GET /cards/{id}/fetch-status` (last scraped-fetch outcome per source), `GET /cards/{id}/match`, `POST|DELETE /cards/{id}/match/{source}` (confirm / reset product URL), `GET /sets` (`?with_stats=true`), `/filters`;
`/scan/identify?slab=1` (adds `slab {grader, grade, cert, tier, grader_seen, cert_sure?, cert_alt?}` or null (`cert_sure: false` = length the grader does not print, not looked up); always read with `slab=1`, in raw mode only when the card is not an exact hit; `detected` is true when raw mode found a slab label, so the page can offer to switch), `/scan/add` (slab = `grading` with optional `grader_name`; answer `stack.duplicate` for an already-owned cert), `/collection` (POST add, GET list with per-item `value/price_kind/source/match/estimated/sources`, `/summary` with `value_by_kind`, PATCH `/{id}` (partial `acquired`: only keys sent change, null clears one; logged), DELETE `/{id}`, POST `/{id}/remove`, POST `/bulk-acquired` (`{ids, acquired}` -> `{updated, unchanged, missing}`), GET `/{id}/history`, POST `/{id}/history/{edit_id}/restore`; list filters (all optional, combined with AND): `q` (name/number), `tcg`, `set`, `rarity`, `type`, `language`, `condition`, `graded`, `grader`, `grade`, `acquisition=<type|unset>`, `cost_missing`, `needs_price`, `stale`, `price_min`/`price_max` (cents per copy, unpriced never match), `pl=positive|negative`, `card_id`; `sort=added|value|cost|pl|qty|name|set|updated` + `order`, `page`, `page_size` (<= 200); answer `{total, items, totals}` where `totals` covers the whole filtered set (stacks, cards, value, cost, pl, pl_ex_pulled, cost_missing, needs_price); `GET /facets`; `GET/POST /presets`, `DELETE /presets/{id}`; add returns `type_conflict`; `/summary` also has `pl_ex_pulled`, `cost_ex_pulled`, `cost_basis_cost(_ex_pulled)`, `pulled_value`, `cost_missing`, `by_type`);
`/wishlist` (GET list `?card_id=` with `value/price_kind/gap/hit/needs_price`, POST add = upsert on card+variant+grade, PATCH/DELETE `/{id}`; a target keeps one linked `auto` alert rule), `GET /cards` items carry `wished`;
`/collection/{id}/sale` (PUT status + listings), `/collection/bulk-sale` (POST non-listed status for many), `/collection/sales/report` (GET ready / listed by platform / sold totals); list params `sale` (none|ready|listed|reserved|withdrawn|active) and `platform`, sorts `asking` / `listed`; totals and `/summary` carry `listed_value`;
`/api/publish/confirm` (POST rows `{item_id, title, description, price, condition, parcel}` = the user's per-item approval), `/api/publish/queue` (GET `?state=&item_id=`), `/queue/next` (POST claim), `/queue/{id}/result|release|cancel|retry` (POST); not in the phone allowlist. `/collection/listing-pack` (POST `{ids, platform vinted|cardmarket, strategy market|under|floor, pct}` -> title / description / price per copy / photo ids / warnings; Vinted items also carry `market_price` and `stored` = last published text + stored price; read-only), `/collection/listing-pack.csv?ids=` (Cardmarket sheet, raw stacks), `/collection/{id}/photos.zip` (cover first; `services/listing_pack.py`), `/collection/{id}/photos` (GET list, POST raw image body `?kind=`), `/photos/{id}?size=full|thumb` (GET bytes), PATCH `{kind, cover, position}`, DELETE, `/photos/stats`; phone: `POST /api/scan/photo?stack_id=&kind=` (allowed through the gate, accepted only for a stack in a recent not-undone scan event); collection list takes `has_photos` and items carry `photo_count` + `cover_photo`;
`/reprice` (GET table: listed rows with market, change, suggested, last sold, `needs_platform_update`), POST `/reprice/confirm` (`{item_id, platform, asking_price}`, app only), POST `/reprice/evaluate`;
`/dashboard/history|breakdown|movers`;
`/alerts` (GET list, POST create, PATCH/DELETE `/{id}`), `/alerts/events` (`?unread=`), POST `/alerts/events/read` (`{ids}` or all), `/alerts/unread-count`, POST `/alerts/evaluate`;
`/admin/catalog/import` (`?sets=` repeatable), `GET /admin/catalog/audit` (live source set list vs stored: new / empty / short / total changed / printed code missing), `/admin/catalog/import/retry-incomplete`, `/admin/prices/refresh` (`?scope=tracked|collection|wishlist&sets=`; 422 otherwise), `POST /cards/{id}/refresh-price` (one card, any card), `/admin/snapshot`, `/admin/jobs`, `/admin/status` (incl. `scheduler.jobs[].next_run`), `/admin/fetcher-status` (`{up, ...}`; 200 even when the fetcher is down), `/admin/prices/fetch` (targets `cards` / `sets` / `owned` / `wishlist` / `missing` = owned cards with a graded stack that has no graded price, or bulk `mode` + `scope` + `stale_days` + `stack_id`), `GET /admin/prices/fetch/current` (running else latest job), `POST /admin/prices/fetch/control` (`{action: pause|resume|cancel}`; 404 none running), `POST /admin/prices/fetch/retry` (re-runs the last job's failures; 422 none); `GET /collection?needs_price=` filter; `/collection/summary` has `needs_price`, `no_data`, `ref_raw_value`, `prices {owned_cards, fresh, stale, never, fresh_days}`.
Health: `/health`, `/health/ready` (pings Mongo).

## Frontend

Vite 8 + Vitest 4 + React 18 + TS + react-router 7 (react-router-dom) + TanStack Query + Tailwind (CSS-variable tokens, class-based dark theme, default dark, light/system toggle) + Radix primitives + lucide icons + Inter + Recharts. All backend calls in `web/src/lib/api.ts`. One colour per price source in `lib/colors.ts`.
Layout: sticky header shell (`App.tsx`: nav, fetcher dot, `ThemeToggle`), container max 1800 px. Theme: `lib/theme.ts` (`useTheme`, `applyTheme`; storage key `moc-theme`; inline script in `index.html` avoids flash). UI kit `web/src/components/ui/` (import from `components/ui`): `Button`, `Card`/`Section` (collapsible, open state in `localStorage` `moc-open:<id>`), `Badge`, `Field`/`Input`/`Checkbox`, `Select` (Radix; `allLabel` = empty value), `Tabs`/`TabList`/`Tab`/`TabPanel`/`SegmentedControl`, `Kpi`, `Skeleton`/`EmptyState`, `Table`/`SortTh`/`Pagination`/`Drawer`, `Combobox` (searchable async single-pick in a Radix Popover: debounced `fetchPage(q,page)` -> `{options, more}`, "Show more" = next page), `Stepper` (− n +, min/max, `disabledInc`), `BarList` (ranked CSS bars, `topN` folds the rest into Other), `cx`. Pages must use these, not raw `select` or hand-rolled button/card styles (the legacy `.btn`/`.card`/`.input` classes are gone). Tokens in `index.css`, mapped in `tailwind.config.js`.

Failure handling: every page query shows `QueryError` (`components/QueryState.tsx`: message + Retry) when the API is down; `ErrorBoundary` wraps the routes (render crash -> reload button); unknown URLs render `pages/NotFound.tsx`. Tests: vitest + jsdom + Testing Library, `fetch` mocked (`src/test/utils.tsx`), `docker compose exec web npm test`.

## Security posture

Local single-user, no auth. API bound to 127.0.0.1 (phone access only through the Tailscale gate, see Phone scanning), CORS limited to the web origin, cross-site writes rejected by an Origin guard, Host header allowlist (`ALLOWED_HOSTS`), Mongo not exposed on host, security headers set. Secrets only in `.env` (gitignored). Add auth before any deployment.

## Performance (measured 2026-10-28, 20,509 cards, local mongo 7)
- Card search is a regex over `search_text` plus filters: a collection scan, 2-25 ms in mongo, 11-190 ms through the API (`q=char` 150-190 ms is mostly the page of 40 cards + owned-qty lookup). Not worth an index at this size. Revisit above ~100k cards or when any path passes 250 ms.
- Collection valuation is in memory: `valuate()` cold = ~190 ms at 2000 synthetic stacks, ~370-560 ms at 5000, ~760-870 ms at 10000 (measured 2026-11-05). Since Step 4 it is cached (`valuation_cache`), so the cost is paid once per change and every list click is a filter/sort over the cached rows: warm list query 5-15 ms at 5000 stacks, 10-34 ms at 10000, facets 12 / 25 ms (`scripts/perf_valuate`, bar: < 100 ms warm at 5000). Paging, sorting and filtering are server-side and in memory, not in Mongo: value, P/L, price range, needs-price, stale and the filtered totals all need the valuation of every matched stack, so a Mongo prefilter would not save the valuation and would add a second code path. Revisit above ~50k stacks.
- Tools (read-only on live data): `scripts/perf_explain.js` (explain table; usage in its header) and `docker compose run --rm -v $PWD/scripts:/code/scripts app python -m scripts.perf_valuate [N ...]` (scratch db `owncollection_perf`, dropped after).
- The text index `cards_text` (15 MB, never queried) is dropped by `init_indexes`.

`pages/Collection.tsx` + `components/collection/` (`Filters`, `PresetBar`, `Grid`, `parts`): URL-synced filters via `lib/urlState.ts` (defaults omitted, page back to 1 on change), search debounced 300 ms, options from `/collection/facets`, filtered-totals strip when a filter is active, table | grid (`ViewToggle`, remembered per device in localStorage `collection.view`). TanStack Query keys `["collection", ...]` (list, summary, facets) use `staleTime` 60 s and `gcTime` 30 min with `keepPreviousData`: returning to the page is instant and refreshes quietly; mutations and fetch jobs invalidate `["collection"]`. The Wishlist page reuses `urlState`, `PresetBar` (scope wishlist) and `ViewToggle`, with search and sort done client-side (`lib/wishlist.ts`).
`components/AcquiredForm.tsx`: shared cost + acquisition form (edit = every field sent, bulk = blank keeps; per-copy or total entry) used by the Collection details drawer (with edit history + restore), the bulk drawer (row checkboxes) and the card page.
`components/CardCollection.tsx` (card page): Owned stack rows (badge, value or "needs price", acquisition badge + paid, edit-cost pencil, qty `Stepper`, delete-confirm `Drawer`) and the Add form (Raw|Graded, estimate from `/compare`); both share the auto-fetch status message.
